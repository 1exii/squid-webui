How Client Onboarding Works

Common to All Clients

Why the Squid Root CA Is Required

HTTPS normally works because your device trusts the public Certificate Authorities that sign website certificates. This Squid proxy inspects allowed HTTPS traffic by acting as a trusted TLS intermediary: it validates the website's certificate, then generates a temporary certificate for that site signed by this deployment's internal Root CA ({{ cert_name }}).

Your device does not trust that private Root CA by default. Install the certificate offered below so browsers and applications can verify the certificates generated by Squid without certificate warnings or HSTS failures. If the proxy Root CA is renewed or replaced, clients must install the new certificate because the previous CA cannot validate certificates signed by the replacement.

Reliable Proxy Routing

Install the Root CA for HTTPS trust, then use the WebUI-hosted Proxy Auto-Config (PAC) file to route browser traffic reliably. Using the same DNS resolver for clients and Squid minimizes CDN destination mismatches. PAC remains recommended because transparent interception can still fail during DNS cache changes or when browsers use Secure DNS.

  • PAC URL: {{ pac_url }} sends Internet traffic through {{ squid_proxy_host }}:{{ squid_proxy_port }} while keeping LAN destinations direct.
  • Router Safety Net: The configured router continues redirecting direct HTTP, HTTPS, and Spotify AP traffic from registered client IPs.

Windows and Ubuntu Use the Same CA Differently

🪟 Windows 10 / 11 / Server

Download the .crt certificate and trust it in the Local Machine Trusted Root store. The Windows installer also configures the current user's system PAC setting and a machine-level Chrome policy; Chrome and Edge then use the Windows trust and proxy configuration.

🐧 Ubuntu / Debian

Download the .pem certificate and add it to the system CA store with update-ca-certificates. The Ubuntu installer also imports it into an existing Chrome/NSS database, installs a managed Chrome/Chromium PAC policy, and configures the active GNOME session when available.

Windows 10 / 11 / Server Client Onboarding Manual

Target Platform: Windows 10/11/Server

1. Automated Installation (Recommended)

Open PowerShell as Administrator, download the installer, and run it in the target user's session. It installs the CA and configures the Windows system PAC setting used by Chrome and Edge.

⬇️ Download Windows Installer (.ps1) 
Set-ExecutionPolicy -Scope Process Bypass
& "$HOME\Downloads\install-windows.ps1"

2. Manual Installation

Step 1: Install the Root CA
Import-Certificate -FilePath "$HOME\Downloads\squid-ca.crt" -CertStoreLocation "Cert:\LocalMachine\Root"
Step 2: Configure the PAC URL
  1. Open Settings → Network & Internet → Proxy.
  2. Under Use setup script, select Set up.
  3. Enable it and enter {{ pac_url }}.
  4. Save, then restart Chrome or Edge.

Ubuntu Linux Client Onboarding Manual

Target Platform: Ubuntu / Debian

1. Automated Installation (Recommended)

curl -sSL {{ webui_public_url }}/download/install-ubuntu.sh | sudo bash

The installer trusts the Squid CA, installs a managed Chrome/Chromium PAC policy, and configures the active GNOME session when available.

2. Manual Installation

Step 1: Download & Install System Root CA
sudo wget -O /usr/local/share/ca-certificates/squid-proxy-ca.crt {{ webui_public_url }}/download/cert.pem
sudo update-ca-certificates
Step 2: Import into Chrome / NSS Certificate Database
sudo apt-get install -y libnss3-tools
certutil -d "sql:$HOME/.pki/nssdb" -A -t "C,," -n "{{ cert_name }}" -i /usr/local/share/ca-certificates/squid-proxy-ca.crt
Step 3: Configure GNOME Proxy Auto-Config
gsettings set org.gnome.system.proxy autoconfig-url '{{ pac_url }}'
gsettings set org.gnome.system.proxy mode 'auto'

Chrome uses the explicit proxy selected by the PAC file; LAN addresses remain direct. The router redirect remains a safety net for applications that ignore desktop proxy settings.

Client Onboarding Troubleshooting

Windows & Ubuntu

Verification & Testing

Open an HTTPS website in Chrome, Edge, or Chromium and confirm that it loads without a certificate warning. You can also test the intercepted command-line path for your operating system:

Windows
curl.exe -v https://google.com
Ubuntu
curl -v https://google.com

Browser Trust & HSTS

  • Edge & Chrome: Restart the browser after installing the Root CA. If a domain's old HSTS state is cached, visit chrome://net-internals/#hsts and delete its domain security policy.
  • Firefox: In about:config, set security.enterprise_roots.enabled to true, then restart Firefox so it uses the operating system's trusted Root CAs.
  • Certificate warnings in every browser: Reinstall the correct Root CA in the machine or system trust store, not only the current user's personal certificate store.

PAC & Proxy Checks

  • Open {{ pac_url }} directly and confirm the PAC file downloads from the client.
  • Confirm the client is configured for automatic proxy setup and restart the affected browser after changing the PAC URL.
  • If only one browser fails, check that browser's certificate and proxy settings before changing the system-wide setup.
